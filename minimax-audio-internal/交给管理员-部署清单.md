# MiniMax 智能配音服务器部署清单

## 一、服务器要求

- Linux ECS 或轻量应用服务器，建议至少 1 核 CPU、1 GB 内存、2 GB 可用磁盘。
- 已安装 Docker Engine 和 Docker Compose v2。
- 服务器允许访问公网 HTTPS（TCP 443），用于调用阿里云百炼和临时 OSS 地址。
- 推荐准备一个已备案的子域名，例如 `voice.example.com`，并将 A 记录解析到服务器公网 IP。
- 安全组只需开放入站 TCP 80、443；不要开放 4173，应用只在服务器本机监听该端口。
- 服务器已有业务时，只新增 Nginx 站点配置，不覆盖原有配置。

## 二、管理员需要准备的三个配置

在服务器的 `.env` 文件中填写：

```dotenv
BAILIAN_API_KEY=公司百炼华北2北京地域的新Key
APP_ACCESS_CODE=发给公司同事的网页访问口令
SESSION_SECRET=至少32位随机字符串
```

可使用以下命令生成 `SESSION_SECRET`：

```bash
openssl rand -hex 32
```

注意：

- 三个值不要写入 Git、企业微信群或部署截图。
- `APP_ACCESS_CODE` 不能与百炼 Key 相同。
- 百炼调用费用记在 Key 所属账号；服务器费用记在 ECS 所属账号。

## 三、部署步骤

将压缩包上传到服务器并解压，然后进入目录：

```bash
cd minimax-audio-internal
cp .env.example .env
chmod 600 .env
```

编辑 `.env`，填入上述三个配置，然后运行：

```bash
./deploy/deploy.sh
```

部署脚本会构建 Docker 镜像、启动容器并执行健康检查。成功后验证：

```bash
curl http://127.0.0.1:4173/api/health
```

应返回包含 `"ok":true` 的 JSON。

## 四、配置访问域名

复制 `deploy/nginx.conf.example` 为新的 Nginx 站点配置，将其中的 `voice.example.com` 替换为实际子域名，然后检查并重载 Nginx：

```bash
nginx -t
systemctl reload nginx
```

再使用公司现有证书系统或 Certbot 为该子域名配置 HTTPS。完成后，同事访问：

```text
https://实际子域名
```

同事只输入 `APP_ACCESS_CODE`，不需要填写百炼 API Key。

## 五、数据、更新与排查

- 音色列表保存在 Docker 数据卷 `minimax_audio_data` 中，重建容器不会丢失。
- 查看状态：`docker compose ps`
- 查看日志：`docker compose logs --tail=100`
- 重启服务：`docker compose restart`
- 更新版本：替换代码后运行 `docker compose up -d --build`
- 停止服务：`docker compose down`，不要增加 `-v`，否则会删除音色数据卷。
- 线上出现异常时，先检查 `/api/health`、容器日志、服务器出站 443 和百炼账号余额。

## 六、验收标准

1. `https://实际子域名/api/health` 返回 `ok: true`。
2. 未输入访问口令时，业务接口返回 401。
3. 登录后页面显示“公司账号已连接”，且没有“API 设置”按钮。
4. 能读取共享音色列表。
5. 使用一段短文本完成一次真实合成并可下载音频。
6. 手机和电脑均能打开，刷新页面后登录状态仍有效。
